# 工作台（`@local/dsh-workbench`）

把会话变成可回溯的工作记录：给每个会话挂**结论、下一步、单号**，一屏看到「进行中 / 未收尾 / 本周收尾」，并能一键生成周报草稿。

左侧栏有一个常驻入口（和 onerway-pmo 同一排），点开就是整页工作台，不占用对话区。

不改 DSH 的会话机制，只在会话旁边加一层旁注；会话事件、标题、时间、归档状态全部从内核派生。

## 怎么用

| 位置 | 说明 |
| --- | --- |
| 左侧栏 | 「工作台」入口（`sidebar.panellist` 席位，order 25），点一下切到整页 |
| 页面顶部 | 三个数字：未收尾 / 本周收尾 / 工作目录内会话；右侧 `刷新`、`复制周报草稿` |
| 第一段 | 进行中 / 未收尾：没有写结论的会话全在这里，**默认不隐藏** |
| 第二段 | 本周收尾：本周一 00:00 到下周一 00:00 之间写了结论的会话 |
| 第三段 | 更早收尾：最多列 20 条 |
| 页面底部 | 工作目录输入框：只收这个目录下的会话，默认 `~/Desktop/work`；改完失焦即存 |

每行点标题会打开对应会话。

## 字段与状态规则

旁注按会话 ID 存一行：

| 字段 | 谁写 | 说明 |
| --- | --- | --- |
| `outcome` | 人 | 结论：这个单最终交付了什么 |
| `next` | 人 | 下一步；留空表示没有后续 |
| `status` | 派生兜底 | 有结论 = `done`；没结论 = `open`；另有 `dropped`（放弃） |
| `impact` / `note` | 人 | 给季度总结和复盘留的字段，面板暂不展示 |

## 任务是怎么认出来的

**任务 = 你主动提到的那个 devops 单号。** 同一个单号出现在几条会话里，就合成一个任务，会话挂在它下面。

判定规则（用真实会话日志定过，宁少不多）：

1. 只看**你自己打的消息**（`source.kind === 'user'`）。会话里大量 `user/message` 其实是注入的上下文——时间、运行时快照、技能清单、AGENTS 规则、上级 agent 的消息——它们会带出与本会话无关的单号，一律不算。
2. 一条消息里**只提到一个单号**才算“我在跟进它”。一次提多个（“拉一下这周的单”“整理本周需求”）属于检索/统计，不命中。
3. 子任务 `RO-…-S04` 归到父需求 `RO-…`；同一个父需求的子任务和父需求算同一个单号。
4. **子会话不参与**：子智能体的会话由父会话代表，算进来只会重复计数。
5. 没有命中单号的会话不算任务，收在「未挂单的会话」里，默认折叠；它们仍然可以写结论。

代价是有些会话会变成「未挂单」（比如标题里有单号、但你从没在对话里提过它）。这是刻意的：宁可少挂，不要错挂。

**归档不算完成**：归档只是把会话从侧栏收起来，一次整批归档不会把 20 件事标成「干完了」。收尾状态只看有没有结论。

## 不做什么

- 不新建任务系统，不做甘特图、不做子任务分解。
- 不写回 devops，不替代任何外部记录系统。
- 不做私人工作台：面板只收工作目录下的会话。
- 不接管官方 UI：只往 `sidebar.panellist`（左侧入口）和 `main`（整页）两个席位里挂东西，不 fork 官方 bundle，不替换任何官方组件。

## 数据存在哪

```text
~/.dsh/workbench/notes.json     # 旁注，按 sessionId
~/.dsh/workbench/config.json    # 工作目录
```

Host 侧路由：`GET/POST /api/workbench/notes`、`GET/POST /api/workbench/config`。

## 测试

```bash
node --test test/host.test.mjs test/client.test.mjs
```

- Host：路由注册、旁注写入与读回、非法输入拒绝、配置持久化（用临时 HOME 隔离）。
- Client：两个座位都注册、快照→行的过滤与状态推导、单号识别、周窗口、周报草稿生成。
